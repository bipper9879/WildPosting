## Workbook layout

`<City>_Workbook.xlsx` must contain a sheet named **`Master`** with this layout:

| Col A | Col B | Col C (Street) | Col D (Job slot 1) | Col E (Job slot 2) | Col F (Google Street View) |
|---|---|---|---|---|---|

Rules:

- **Column C** holds the street/intersection name. This is the canonical name
  matched against the `<City>_Master\<Street>\` folder name.
- **Columns D and E** are the two job slots. Put a *number* in either (or both)
  to mark the row as in-scope for the next run. Leave blank, or use placeholder
  text like `job1` / `job2` - those are ignored by the row-include filter and
  also stripped out of the new dated sheet.
- **Column F** holds Street View hyperlinks generated by either
  `LinkGenerator.ps1` (writes into Master sheet) or by `Create_poster_Pics.ps1`
  while building the dated sheet.

## Daily workflow

1. Connect phone, copy the day's poster pics into `posters\TEsting_auto\`.
2. Open `<City>_Workbook.xlsx`, on the **Master** sheet put a number in
   columns D or E for every row you want included today.
3. Run `Create_poster_Pics.ps1` (or double-click `Launcher.vbs` for a hidden
   run). Enter the city code and select today's date.
4. Watch the four-stage progress bar:
   - Filtering Master rows
   - Writing dated sheet + Street View links
   - Loading GPS anchors
   - Sorting photos
5. Review `<City>_log.txt`. The `[SUMMARY]` line shows totals; per-photo lines
   include best match, distance, runner-up street, and resolved destination.
6. Anything in `Needs_Manual_Sorting\` gets dragged manually.

## Scripts

### Create_poster_Pics.ps1

The main orchestrator. Pops a WinForms dialog for **City** + **Date**
(`MM-dd-yyyy`) and runs the full pipeline:

1. Open `posters\<City>\<City>_Workbook.xlsx` via Excel COM.
2. Read the `Master` sheet. Filter rule: include row if column C has a street
   name **AND** (column D or column E parses as a number).
3. Add (or clear and reuse) a sheet named after the selected date, e.g.
   `06-15-2026`. The sheet:
   - **Header row** is copied from Master row 1 via `Range.Copy`, preserving
     text and formatting. So renaming the D/E headers on Master flows through.
   - **Filtered rows** are copied across using `Range.Copy` per row.
   - **Cells in D/E that contain literal `job<n>`** (case-insensitive: `job1`,
     `Job 2`, `JOB10`) are wiped on the new sheet only. Numbers and any other
     text pass through unchanged.
   - **Column F** gets a `Google Street View` header and per-row hyperlinks.
     Each row's link is built from the average GPS of pictures inside
     `<City>_Master\<Street>\` (exact name first, then a fuzzy match that
     strips leading numbers, NW/NE/SE/SW, and non-alphanumerics).
4. **Reorder tabs**: today's sheet to position 1 (leftmost), `Master` to
   position 2, then any other `MM-dd-yyyy` sheets sorted newest-first.
5. **Activate** today's sheet and select cell A1, so the next time the
   workbook is opened manually it lands on the new tab.
6. Save and close the workbook.
7. Build the per-run folder tree under `posters\<City>\<MM-dd-yyyy>_<City>\`
   for every filtered street, plus `Needs_Manual_Sorting\`.
8. Load GPS anchors:
   - **Primary**: `<City>_Master\<Street>\` (drift-corrected, trusted source).
   - **Fallback**: previous `MM-dd-yyyy_<City>` runs - only if Master has
     nothing for that street.
9. For every image in `posters\TEsting_auto\`, read EXIF GPS, find the closest
   anchor and the closest anchor on a *different* street (the runner-up).
   Move into the matching street folder if within `$MatchRadiusFeet` of the
   best anchor; otherwise move into `Needs_Manual_Sorting\`.
10. Write `posters\<City>\<City>_log.txt` and open the dated folder + log.

**Trigger rules at a glance**

| Column C | Column D | Column E | Result |
|---|---|---|---|
| empty | anything | anything | row ignored |
| has text | empty | empty | row ignored |
| has text | `job1` | empty | row ignored (no number) |
| has text | `5` | empty | folder created, row copied |
| has text | empty | `3` | folder created, row copied |
| has text | `5` | `3` | folder created, row copied |
| has text | `Steve` | `2` | folder created, row copied |

**Log format**

Each fresh image produces one of:

```
[MOVED]   IMG_xxx.jpg [GPS lat,lon] -> [Street] N ft (limit X ft [override]?); runner-up [OtherStreet] M ft -> <full destination path>
[CLUSTER] IMG_xxx.jpg [GPS lat,lon] -> [Street] via timestamp cluster (matched K neighbor(s) within +/-90s ...). GPS-closest [...] was over limit -> <destination>
[MANUAL]  IMG_xxx.jpg [GPS lat,lon] -> Closest [Street] N ft (limit X ft); runner-up [OtherStreet] M ft
[MANUAL]  IMG_xxx.jpg -> No GPS metadata in file.
[ERROR]   IMG_xxx.jpg ... (anchor matched but no folder for street, or move failed)
```

Other notable lines:
- `[RADIUS] [Street] override = N ft (from .radius file)` - one per street
  with a per-street override active.
- `[PROCESSING] Per-street overrides: Street1=N1; Street2=N2; ...`
- Final `[SUMMARY]` line shows total / GPS-moved / cluster-moved / manual /
  errors.

**Knobs you can tweak in-script**

- `$MatchRadiusFeet = 35` - global default.
- `$ClusterWindowSeconds = 90` - +/- window for the timestamp-cluster fallback.
- Per-street radius is set via `<City>_Master\<Street>\.radius` (see Tuning).
- Anchor priority order (Master then history) is hard-coded in the loader.

**Common errors**

- *`Cannot convert value "0" to type XlCutCopyMode`* - happened when the
  Office.Interop.Excel typelib is loaded. Removed; the property is purely
  cosmetic and only matters when Excel is visible (we run hidden).
- *Parse errors mentioning string terminators* - means the file got saved
  with non-ASCII characters (em dashes, box drawing) and PowerShell 5.1
  read it as Windows-1252. Fix: keep `.ps1` files pure ASCII or save as
  UTF-8 with BOM.

### LinkGenerator.ps1

Standalone Street-View-link generator that writes hyperlinks into **column F
of the `Master` sheet**. Use it after curating Master if you want the master
sheet itself to have working links (the dated sheets get their links built
directly by `Create_poster_Pics.ps1`).

Steps:

1. Prompts for City code if not passed in via `-City <code>`.
2. Opens `<City>_Workbook.xlsx`, sheet `Master`.
3. For every row, finds the matching `<City>_Master\<Street>\` folder. Exact
   name match first, then fuzzy normalization (leading number strip,
   NW/NE/SE/SW strip, non-alphanumerics removed, lowercased).
4. Averages EXIF GPS from every image in that folder.
5. Writes a `Street View` hyperlink in column F that points to:
   `https://www.google.com/maps/@?api=1&map_action=pano&viewpoint=<lat>,<lon>`

Special cells:

- `No GPS Photos Found` - matched the folder but no images had EXIF GPS.
- `Subfolder Missing` - no folder with that name (or fuzzy variant) exists.

### Compare-MasterList.ps1

Reconciles `<City>_Master\` subfolder names against the Master sheet's
column C. Read-only; the workbook is opened with the ReadOnly flag, so it
won't fight Excel if the workbook is open.

Three buckets:

- **Only in folder** - directory exists on disk, no row in column C.
- **Only in workbook** - row in column C, no folder on disk.
- **Matched** - present in both.

Also flags **duplicate names inside column C** (case-insensitive) so you can
catch typos like `Georgia Ave` vs `georgia ave`.

Comparison is case-insensitive but does not apply the
`LinkGenerator`/`Create_poster_Pics` fuzzy normalization. So
`8 Georgia Ave NW` and `Georgia Ave NW` are reported as different.

Switches:

```powershell
.\Compare-MasterList.ps1                  # default city DC
.\Compare-MasterList.ps1 -City Philly
.\Compare-MasterList.ps1 -ShowMatched     # also list matched entries
.\Compare-MasterList.ps1 -ExportCsv       # write <City>_MasterDiff_<stamp>.csv
```

Exit codes: 0 = identical, 1 = mismatches found.

The script shows a `Write-Progress` bar through folder scan, workbook open,
per-row read, and comparison.

### Debug-PhotoGps.ps1

A GPS dumper for diagnosing why a particular photo did not land where you
expected. Uses the same EXIF parser as `Create_poster_Pics.ps1` and the same
haversine formula.

```powershell
# List GPS for everything currently in TEsting_auto
.\Debug-PhotoGps.ps1

# Aim at any folder
.\Debug-PhotoGps.ps1 -Folder "C:\path\to\folder"

# Compute each photo's distance to a Master street's centroid
.\Debug-PhotoGps.ps1 -Sample "5th btw Neil Pl & Morse NE"
.\Debug-PhotoGps.ps1 -Folder "C:\path\to\folder" -Sample "1211 Connecticut NW" -City DC
```

Output is a table of `File | Lat | Lon | FtToSample`, plus a "within 100 ft"
sub-list when `-Sample` is provided.

If `FtToSample` is huge but the photo really was at that spot, the phone's
EXIF was off (urban canyon - see below). Curating Master with cleaner
anchors fixes the centroid.

If `FtToSample` is small but the photo did not get sorted there, an even
closer Master anchor on a different street is winning. The
`[MOVED] ... runner-up [...]` field in `<City>_log.txt` will name the rival.

## GPS / urban canyon notes

Phone GPS is fundamentally line-of-sight to the satellites. Tall buildings
on one side of the street block the southern half of the sky (where most
satellites sit at mid-latitudes), and glass facades reflect signals back
into the receiver - that's *multipath*. The combined effect is

- **Drift can be 30-150 ft** along narrow east-west streets with mid-rises
  on the south side.
- **Drift is usually directional, not random.** Multiple shots on different
  days from the same physical spot tend to land in the same wrong cluster.
- **Northeast/west of the Capitol** (H Street NE, NoMa around Neal Pl /
  Eckington / Morse / Florida) and **Connecticut Ave between Dupont and K**
  are the worst offenders in DC right now.

How this affects the sorter:

- A photo's recorded GPS may be 50-100 ft from the true spot.
- That can put it inside the radius of a *neighboring* intersection's anchor.
- The sorter has no way to recover the truth from EXIF alone - it can only
  match what the phone wrote.

Mitigations:

- **More anchors per Master folder, taken on different days and times.** The
  centroid averages out and ends up close to the true spot.
- **Smaller radius** keeps cross-street collisions down at the cost of more
  manual sorting.
- **Don't consolidate distinct intersections** even when they read like
  variants - e.g. `Connecticut Ave & Rhode Island Ave NW` is genuinely a
  different physical spot from `Rhode Island & Connecticut Ave NW` if your
  workflow treats them as separate poster locations.

## Tuning the match radius

`$MatchRadiusFeet` in `Create_poster_Pics.ps1` defaults to **35 ft** today.

| Radius | Behavior |
|---|---|
| 25 ft | Very tight. Most GPS-clean photos hit; canyon photos fall to manual. |
| 35 ft | **Current default.** Catches the boundary cases like 32-37 ft drift. |
| 50 ft | Captures more, but adjacent intersections start trading photos. |
| 100 ft+ | Captures almost everything but cross-talk is rampant in NoMa. |

### Per-street radius override (`.radius` file)

For streets in known urban canyons where 35 ft is not enough, drop a single
text file named `.radius` inside the Master folder:

```
<City>_Master\<Street>\.radius
```

The file should contain just a positive integer (the radius in feet).
Whitespace / line endings are fine. The script reads it during anchor
loading and applies it only to that one street; everywhere else uses the
global default.

DC defaults seeded based on ground-truth analysis of the 06-14-2026 run:

| Master folder | Override |
|---|---|
| `5th btw Neil Pl & Morse NE` | 200 ft |
| `Florida & Porter NE` | 150 ft |
| `Connecticut  Ave & Rhode Island Ave NW` | 110 ft |
| `H St & 14th St NE` | 100 ft |
| `1211 Connecticut NW` | 80 ft |
| `8th ST & V ST NW` | 50 ft |

The log line `[RADIUS] [<Street>] override = N ft` confirms each load.
`[MOVED]` lines now also show whether the radius used was the default or
an override.

> **Note:** The 200 ft override on `5th btw Neil Pl & Morse NE` is unusual.
> The Master centroid for that street is ~180 ft off the actual location,
> indicating one or more bad anchor photos in the Master folder. Re-curate
> with cleaner GPS shots and the override can be lowered.

### Timestamp-cluster fallback

For photos whose recorded GPS is so wrong that even the override can't
catch them (phone EXIF off by 100+ ft, common on Connecticut Ave between
Dupont and K), the sorter falls back to a *timestamp cluster* check:

- Looks at the photo's `IMG_yyyyMMdd_HHmmss_*` filename to extract a wall
  clock time.
- Searches every photo *successfully moved by GPS* in the same run within
  +/-90 seconds.
- If those neighbors all agree on a single street, this photo gets sent
  there too with a `[CLUSTER]` log tag.

The fallback only fires when the GPS pass alone would have failed, and
only when neighbors are unanimous. Non-unanimous clusters fall through
to `Needs_Manual_Sorting`.

The cluster window is `$ClusterWindowSeconds = 90`, hard-coded near the
top of the photo-sort phase. Bump it if your route has long gaps between
shots, but be careful: a wider window can grab unrelated streets and
mis-route.

## Curating the `<City>_Master` folder

The Master folder is the source of truth - everything else flows from it.

Rules of thumb:

1. **2-6 GPS-clean pics per street.** More than 6 starts diluting the
   centroid if the spot drifted between visits.
2. **Take anchor pics in clear sky conditions** when possible (sunny midday,
   not rainy/cloudy). Better satellite locks = tighter centroid.
3. **Periodically retire bad anchors.** If a street keeps misrouting,
   `Debug-PhotoGps.ps1 -Sample "<Street>"` will show which Master pic is
   pulling the centroid the wrong way.
4. **Keep folder names matching column C exactly** for the cleanest match.
   The fuzzy fallback works but is not infallible.
5. **Run `Compare-MasterList.ps1` after any reorganization.** Catches typos,
   missing folders, and orphan rows in one shot.

Workflow when adding a new street:

1. Take 2-3 GPS-clean photos at the spot.
2. Create `<City>_Master\<Street>\` with that exact name.
3. Drop the photos in.
4. Add a row to the Master sheet column C with the same name.
5. Run `Compare-MasterList.ps1` to confirm zero mismatches.
6. Optionally run `LinkGenerator.ps1` to populate the Master-sheet column F
   Street View link.
